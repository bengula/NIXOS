# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Personal NixOS configuration for the host `Erudite`, organised with the
**Dendritic Pattern**: `flake-parts` + `import-tree`. Every `.nix` file under
`flakes/modules/` is a flake-parts module loaded automatically — there is no
import list to maintain. A file becomes part of the system by existing, and a
file can contribute to multiple module classes at once (e.g. both a NixOS
module and a Home Manager module).

## Commands

```bash
# Rebuild and switch the running system (from repo root)
sudo nixos-rebuild switch --flake ./flakes#Erudite

# Build just the wallpaper shader renderer — much faster than a full
# nixos-rebuild when iterating on a build failure there
nix build ./flakes#orbit-wallpaper-engine

# Regenerate the (currently stale) flake.lock after adding/changing inputs
nix flake update   # or: nix flake lock
```

There is no test suite; validation is `nixos-rebuild switch` (or `build`)
succeeding and the resulting session behaving correctly.

**This is a git flake — Nix only sees tracked files.** After adding a new file
under `flakes/modules/`, `git add` it before rebuilding, or the change is
invisible to Nix.

## Architecture

`flakes/flake.nix` is the entire entrypoint:

```nix
outputs = inputs:
  inputs.flake-parts.lib.mkFlake { inherit inputs; } (inputs.import-tree ./modules);
```

Each file under `flakes/modules/` describes one **aspect** of the machine and
writes into a shared namespace (declared by `modules/parts.nix` via
`flake-parts.flakeModules.modules`):

- `flake.modules.nixos.<aspect>` → a NixOS module
- `flake.modules.homeManager.<aspect>` → a Home Manager module

`modules/terminal.nix` is the canonical example of one file owning both sides
(system package + user profile) so one concern isn't split across two places.

**Aspects are only published, not switched on, by existing.** `modules/hosts.nix`
is the single place that assembles aspects into `flake.nixosConfigurations.Erudite`
— that file's module list is what actually determines what the machine is made
of. Adding a new aspect requires both dropping the file in `modules/` *and*
adding its name to the list in `hosts.nix`.

Non-module code lives alongside `modules/`:
- `flakes/services/bengula-portal.nix` — a long-form NixOS module (options +
  systemd + nginx), kept out of `modules/` because of its size; published as
  an aspect by `modules/bengula-portal.nix`.
- `flakes/pkgs/` — package derivations (`bengula-portal.nix`,
  `orbit-wallpaper-engine.nix`), consumed via `pkgs.callPackage` from the
  services/modules that need them.
- `flakes/hosts/erudite/hardware.nix` — generated by `nixos-generate-config`;
  published as an aspect by `modules/hardware-erudite.nix`. Edit cautiously.

### Interlocking systems worth knowing before touching them

- **Hyprland keybindings** (`modules/hyprland-keys.nix`) are a single source
  list that generates three things at once — the searchable wofi palette
  (`Super + /`), the which-key modes (resize/window), and the waybar mode
  indicator — so they can't drift apart. Changing a binding means editing
  that one list, not the three consumers.
- **Locking** (`modules/lock.nix`) is the one entry point (`hypr-lock`) used
  by the idle timer, the lid switch, and `Super + Escape` alike, so all three
  paths keep logind's `LockedHint` consistent. It also drives
  `modules/wallpaper.nix`'s intro/exit shader sequence via a control FIFO —
  every signal there is optional and time-bounded (missing FIFO = no-op) so a
  cosmetic wallpaper can never wedge the lock screen; it degrades to plain
  hyprlock if the renderer isn't running.
- **hypridle** is bound to `hyprland-session.target`, not
  `graphical-session.target` — GNOME has its own idle handling, and both
  running is worse than either alone. The wallpaper renderer uses the same
  target for the same reason (it needs `wlr-layer-shell`, which doesn't exist
  under GNOME).
- **Terminal transparency** (`modules/terminal.nix` + `desktop-hyprland.nix`)
  needs two settings in lockstep: `use-theme-transparency = false` (GTK theme
  would otherwise override the percentage) and the Hyprland blur/`layerrule`
  config. Adjust both halves together.
- Two independent animation systems exist because hyprlock doesn't use
  Hyprland's: the session's lives in `desktop-hyprland.nix`, the lock
  screen's in `lock.nix`.

### Users

`modules/home-manager.nix` wires Home Manager into NixOS and maps system
users to Home Manager aspects (`modules/home-bebe.nix`, `modules/home-pri.nix`),
which import a shared `modules/home-base.nix` plus whichever
`homeManager.<aspect>` modules apply to that user.

## Known rough edges (deliberate, see README.md for full detail)

- `flake.lock` predates several inputs and needs `nix flake update`.
- `pkgs/bengula-portal.nix` has `npmDepsHash = lib.fakeHash` — harmless while
  `services.bengulaPortal.enable` is `false`; must be filled in (per the
  comment in that file) before enabling the portal in `hosts.nix`.
- `boot.loader.grub.device = "/dev/sda"` — not stable across hardware changes;
  change deliberately.
- `networking.nameservers` hardcodes Google DNS, overriding DHCP.
- `services.openssh.enable = true` allows password auth by default.
